## Defaults and security limits

Owner-approved admission change (2026-11-10): remove daily portfolio-open quotas. Configurable protective defaults are token buckets allowing 60 opens/minute per full visitor hash (burst 60), 240 admission attempts/minute globally (burst 240), and four active requests for at most 120 seconds. These are short-term abuse settings, not account/product quotas or promises of monthly capacity. Set optional server-only Convex environment variables `TIKR_BROWSE_PER_MINUTE` (1?600), `TIKR_BROWSE_GLOBAL_PER_MINUTE` (1?2400), and `TIKR_BROWSE_CONCURRENCY` (1?16); invalid values fail closed. Defaults are conservative operating choices informed by the synthetic measurements below, not measured platform allowances. Changing environment configuration or deploying requires separate authorization.

Vercel derives the full 256-bit HMAC-SHA256 of its overwritten visitor header using the private gateway key and a domain separator. No raw IP is persisted or logged, and no 128-bucket projection remains. Visitors sharing a network may still share a limit; this is abuse protection, not identity or ownership. At most 256 visitor hashes are retained, each for ten minutes from registration. A scheduled internal expiry removes only expired anonymous limiter state; entry also checks expiry. A full registry fails with retry timing rather than evicting a live visitor. Expiry never clears historical counters, refresh attempts, locks, abandoned guards or revocations. Existing day/open/bucket fields are preserved as historical counters and no longer enforced. The rate-limiter component is mounted in `convex/convex.config.ts`; a future authorized deployment must include it. Local tests register the actual component; no deployed binding verification is claimed. Bodies remain capped at 12,000 bytes, three portfolios and six supported assets. Full origin/Host/content-type checks apply in production and reject missing Origin; these checks are not authentication against non-browser clients.

The HTTP gateway accepts only bearer-authenticated read/acquire/write/release/control operations; it cannot configure budgets or call arbitrary functions. Internal market functions remain internal. Existing cache lease tokens, one daily automatic refresh and bounded explicit retry are shared by every instance. The shared calendar also uses durable cache/lease admission. Revocations and symbol refresh guards reside in a bounded Convex control document and survive instances/restarts/month changes. An uncertain refresh leaves its guard indefinitely; expiry of a work lease never clears a guard. Wrong-token finish cannot clear another writer's guard. Storage errors block results; there is no filesystem fallback or alternate provider.

Application budgets cannot prevent the platform from charging for HTTP requests, rejected calls or transaction retries. Configure Vercel firewall/rate limits and platform spend alerts before public activation; direct anonymous floods and gateway abuse need platform enforcement. No free-tier or cost guarantee is claimed. The global control document intentionally trades throughput for serialized bounded admission at this small scale.

Unset `TIKR_HOSTED_DATA_ENABLED` in Convex first to close the gateway immediately, then unset it in Vercel and redeploy. Rotate the private gateway credential in both environments after any suspected disclosure, without logging it. Roll back Vercel source through its deployment console; retain additive Convex tables and counters. Recovery from a retained guard/revoked policy requires operator investigation and a separately reviewed policy/scope revision. Budget review expiry fails closed; renew from actual team evidence, not a reset.

## Server diagnostics (2026-11-06)

Server logs emit JSON `market_failure` events with fixed `stage` and exact allowlisted `code` only. Stages identify origin, admission, configuration, calendar, runtime and stream failures; nested failures may emit multiple events. Unknown exceptions become `UNKNOWN_FAILURE`; raw exceptions, request bodies, IPs, credentials and financial values are never logged. Client responses expose only the bounded market failure vocabulary and retry timing, never raw exceptions. `VISITOR_REQUIRED` means the trusted Vercel header is absent/oversized; `HOSTED_CONFIG` means the gateway URL or key shape failed before fetch. Neither bypasses admission. A calendar failure can occur during gateway cache access before any Alpaca call.

Canonical `ALPACA_API_KEY_ID` / `ALPACA_API_SECRET_KEY` take precedence independently. Legacy `APCA_API_KEY` / `APCA_API_SECRET` are accepted only when the corresponding canonical variable is absent. Empty or whitespace-containing credentials fail closed; delete empty canonical variables to use fallback. Configuration changes require a new Vercel deployment. These logs do not establish production root cause or validate credential entitlement. Inspect server logs for the failing stage/code, verify both environment scopes and the gateway/budget prerequisites above, then redeploy only with authorization. Never reset counters or guards to resolve an availability error.

## Admission behavior and measured local operations (2026-11-10)

Cached opens still consume the shared Convex admission budget and recheck calendar/dependency revisions, correction guards and revocations. Missing/stale sources acquire the existing shared durable leases before provider work; every provider request retains its 2 MiB reservation on success or failure. The existing 100 MB storage / 500 MB monthly admission I/O / 250,000 admission-call caps and team-review gate are unchanged. Release/finish/revoke remain possible when the budget is exhausted. A calculation-slot lease refusal skips persistence without refusing an otherwise valid calculation from fresh assets; it cannot authorize provider work.

Manual source retries remain server-enforced: one automatic attempt per New York daily cycle, one additional explicit attempt, at least 60 seconds after the previous attempt. Concurrent writers still share a busy lease. Cooldown failures return the known deadline; exhausted cycle attempts return the next New York 09:00 cutoff, including DST. A busy/abandoned correction guard is never expired by visitor cleanup. UI copy distinguishes browsing rate limits, refresh cooldowns, shared budget exhaustion, pending budget review and missing history; retry times are shown when known. The gateway and pre-stream route use HTTP 429 plus `Retry-After` for rate/cooldown refusal, 503 for budget/data unavailability. Explicit retries await settlement before committing headers, allowing a blocked cooldown to return 429. A normal streamed failure discovered after headers carries its code/deadline in NDJSON; HTTP status cannot be changed then. Dated stale results retain their date and safe failure explanation.
